## 学习笔记（脚手架，请补自己的理解）

### 为什么要学
- Prompt 不是「怎么问 AI」的咒语，而是把任务目标、输入边界、输出格式、失败处理和安全规则写进一次可执行的沟通协议。
- 没有边界的 prompt 会让模型自然「补完」缺失信息：编出不存在的 API、误解用户目标、把草稿当确认结果。好的 prompt 不是让模型更自信，而是让模型在合适的时候停下来。

### 第一性原理
- **Prompt 是软约束，不是安全边界**。真正的边界由代码、权限、校验、审计承担。
- 指令分层要清楚：系统规则 / 开发者规则 / 用户目标 / 检索内容不能混在一起。
- 输出格式要机器可检验：JSON schema、函数参数、明确字段。
- 高风险动作（写库、发消息、调工具、支付、签名）不能只靠 prompt 拦截，必须再过代码层校验 + human check。

### 知识节点
- **Instruction**：给模型的任务规则——角色、目标、禁止行为、不确定时怎么办、输出形态。要区分「解释」和「执行」。实用写法拆四段：任务目标 / 可用输入 / 禁止行为 / 输出格式和失败格式。
- **Few-shot**：在 prompt 里放少量示例传递风格和边界；示例不是一次性素材，要跟 eval 一起维护，协议升级后旧示例会反过来误导。
- **Structured Output**：固定 JSON / 函数参数，让后续代码能检查、拒绝、记录、回归测试。不是为了好看，是为了可处理。
- **Prompt Injection**：攻击者通过用户输入、网页、文档、邮件、检索内容让模型忽略规则、泄露信息、调用危险工具。应对不靠「写一句别被注入」，靠：外部内容标记为不可信数据、工具调用前参数校验、敏感动作走 allowlist + human approval、不把密钥和不可撤销动作交给模型。

### 在 AI x Web3 中的位置
Prompt 处在用户目标和模型行为之间，它把「帮我看看这笔交易有没有问题」变成可执行任务。但安全不能只靠 prompt，更稳的链路是：Prompt 定义任务和输出格式 → Context 提供可信数据和来源边界 → Model 生成解释或候选动作 → Code 校验 schema 和业务规则 → Guard / simulation 检查链上影响 → Human check 确认高风险动作。

## 我的理解 / 疑问

**我的理解**（你的话，Learning Agent 润色）：

1. **Prompt 负责约束输出，不负责校验输出。** Prompt 只能提高模型遵循任务的概率，不能保证它一定对——「约束」和「校验」是两件事：约束靠 prompt 表达任务，校验靠代码 / schema 确认结果。
2. **结构化输出重要，是因为它可以被验证。** 机器要处理的是明确字段（`risk_level`、`requires_human_approval`…）而不是散文，只有固定结构才能被检查、拒绝、回归测试——正好接上「输出格式要机器可检验」。
3. **数据库操作（写库）这类动作，绝对不能只靠 prompt 拦住。** 它是高风险动作，必须再过代码层校验和人工确认——因为 prompt 可能被注入，或模型把草稿当确认结果，软约束扛不住真实副作用。
