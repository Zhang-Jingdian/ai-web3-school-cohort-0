## 学习笔记（脚手架，请补自己的理解）

### 第一性原理
- LLM 生成的是概率上合理的输出，不是天然可信的事实 → 把模型当推理层，不当真相源。
- 关键事实必须来自数据库 / API / 日志 / 文档源等可信系统。

### Token
- token ≠ 一个字 / 一个词，是 tokenizer 切分后的片段；决定上下文容量、成本、能否看见关键信息。
- 误区：「页面短」≠「token 少」，代码 / JSON / 地址 / 表格更吃 token。

### Embedding
- 把文本映射成向量，衡量「语义接近」，用于搜索 / 聚类 / RAG。
- 边界：向量相似 ≠ 结论正确，不能替代来源校验。

### Hallucination
- 幻觉 = 看起来合理但不真实 / 无法验证的内容（编 API、错引资料、把旧文档当当前状态）。
- 处理不靠「更好的 prompt」，靠外部校验：来源引用、schema 校验、规则检查、人工确认、审计日志。

### Transformer / Multimodal（推荐路径）
- Transformer 的 attention 让模型在上下文里找模式，但「擅长找模式 ≠ 拥有稳定数据库」。
- Multimodal 让模型读懂图表 / 控制台 / 错误截图，但关键判断仍要回到结构化数据。

### 在 AI x Web3 中的位置
四层：数据层（RPC / 索引器 / 预言机 / 向量库）→ 编排层（Prompt / Context / RAG / Agent）→ 执行层（工具调用 / 钱包 / 合约）→ 安全层（Guard / 模拟 / 权限 / 日志）。越靠近执行层，越要把自然语言输出变成可验证对象。

## 我的理解 / 疑问

**我的理解**（自己组织，Learning Agent 润色）：
LLM 的流程是——Transformer 架构把输入拆成 token，再映射成 embedding（向量），然后基于概率生成输出。两个容易引发幻觉的点：

1. 输入超过上下文长度 → 关键信息被截断丢失 → 模型只能靠概率补齐 → 产生幻觉；
2. embedding / 检索没做好 → 拿不到对的上下文 → 也会产生幻觉。

**第一性原理（根因）**：LLM 本质是概率模型，它生成的是「最像的下一个词」，而不是「查证过的事实」。上面两个只是让它更容易出错的触发器——就算上下文够、检索对，它仍可能编造。所以关键事实必须来自可信系统（数据库/API/日志），模型只当推理入口，不当真相源。

**一句话答案（试金石）**：LLM 到底在做什么？——它在**猜下一个最可能的 token**，不是在查事实。

**触发器 vs 根因（别混淆）**：
- 触发器（让幻觉更容易发生，但不是原因）：上下文超长被截断、检索/embedding 没拿对材料。
- 根因（本质）：概率模型永远在「预测最像的下一个词」，不是「查证事实」。所以哪怕上下文够、检索对，它仍可能编造。
