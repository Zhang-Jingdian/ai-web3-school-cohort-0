## 学习笔记（脚手架，请补自己的理解）

### 为什么要学
- Prompt 不是「怎么问 AI」的咒语，而是把任务目标、输入边界、输出格式、失败处理、安全规则写进一次可执行的沟通协议。
- 好的 prompt 不是让模型更自信，而是让模型在合适的时候停下来。

### 第一性原理
- **Prompt 是软约束，不是安全边界**。真正的边界由代码、权限、校验、审计承担。
- 指令分层要清楚：系统规则 / 开发者规则 / 用户目标 / 检索内容不能混在一起。
- 输出格式要机器可检验：JSON schema、函数参数、明确字段。
- 高风险动作（写库、发消息、调工具、支付、签名）不能只靠 prompt 拦截。

### 知识节点
- **Instruction**：角色、目标、禁止行为、不确定时怎么办、输出形态。实用写法拆四段：任务目标 / 可用输入 / 禁止行为 / 输出格式和失败格式。要区分「解释」和「执行」。
- **Few-shot**：用少量示例传递风格和边界；示例不是一次性素材，要跟 eval 一起维护，协议升级后旧示例会反过来误导。
- **Structured Output**：固定 JSON / 函数参数，让后续代码能检查、拒绝、记录、回归测试。
- **Prompt Injection**：外部输入/网页/文档/邮件/检索内容都可能注入指令。应对靠：外部内容标记为不可信数据、工具调用前参数校验、敏感动作走 allowlist + human approval、不把密钥和不可撤销动作交给模型。

### 在 AI x Web3 中的位置
Prompt 定义任务和输出格式 → Context 提供可信数据和来源边界 → Model 生成解释或候选动作 → Code 校验 schema 和业务规则 → Guard / simulation 检查链上影响 → Human check 确认高风险动作。
